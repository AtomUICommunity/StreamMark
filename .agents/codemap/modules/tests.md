# 测试项目

两个 xunit.v3 测试项目（`StreamMark.Avalonia.Tests` 29 个 `.cs`、`StreamMark.Core.Tests` 14 个）：`StreamMark.Core.Tests` 是纯逻辑测试，靠从 vercel/streamdown 录制的 JSON golden fixture 回放 remend，并对流式快照做属性测试；`StreamMark.Avalonia.Tests` 用 `Avalonia.Headless` + Skia **真实渲染**，通过 `HeadlessApp` 把控件显示在无头窗口里，断言控件树 / 布局 / 选区 / 真实像素，并把 PNG 写到截图目录供人查看。

**不负责：** 生产代码（`src/**`，见各业务模块页面）；基准测试（`bench/StreamMark.Benchmarks`、`bench/StreamMark.CpuHarness`）；Gallery 的 AOT 冒烟（`.github/workflows/ci.yml:121` 的 `--smoke`）；fixture 的生成脚本本身（`tools/remend-fixtures/extract.mjs`，本模块只消费它的产物）。

## How to extend
- **新增 remend fixture**：先在 remend 上游跑 `node tools/remend-fixtures/extract.mjs <pkgDir> <depsDir> <outDir>`（用法与依赖见 `tools/remend-fixtures/extract.mjs:9-11`，它会断言 TS 套件自身通过，`:75`），把生成的 `<name>.json` 放进 `tests/StreamMark.Core.Tests/Fixtures/remend/`，**然后改 `RemendFixtureTests.EveryTestFileHasFixtures` 里的 29**（`tests/StreamMark.Core.Tests/Remend/RemendFixtureTests.cs:35-38`）。漏掉第二步 → 该断言失败，即使回放全过。若新 fixture 引入了新的 `fn` 名，还要在 `Invoke` 的 switch 里加分支（`:150`），否则每个 case 都报 `unknown fixture function`；新的 `linkMode` / 选项名同理在 `ParseOptions` 里加（`:99`）。
- **新增 markdown fixture**：把 `<name>.md` 放到 `tests/StreamMark.Core.Tests/Fixtures/streaming/`。Core 侧靠 `Fixtures\**\*` 自动进输出目录（`tests/StreamMark.Core.Tests/StreamMark.Core.Tests.csproj:17`）；Avalonia 侧靠跨项目 glob 自动摊平复制（`tests/StreamMark.Avalonia.Tests/StreamMark.Avalonia.Tests.csproj:22`），两端因此**同时**能看到这个文件（`HeadlessApp.Fixture` 与 `StreamingEquivalenceTests.Fixture`）。但**必须把它加进 `StreamingEquivalenceTests.Cases`**（`tests/StreamMark.Core.Tests/Streaming/StreamingEquivalenceTests.cs:18`），否则它只是一个被复制的死文件，没有任何等价性断言覆盖；只在 Avalonia 侧用则直接 `HeadlessApp.Fixture("<name>.md")` 即可（`tests/StreamMark.Avalonia.Tests/Transcript/TranscriptViewTests.cs:46`）。
- **新增需要真实渲染的测试**：新建 `tests/StreamMark.Avalonia.Tests/<Area>/<Thing>Tests.cs`，复制 `HeadlessApp.Run` + `Window.Show()` + `Settle()` + `ApplyLatest()` + `Settle()` 骨架（`tests/StreamMark.Avalonia.Tests/Rendering/MarkdownViewSnapshotTests.cs:13-22`），断言后可选 `HeadlessApp.Save(window, "<name>")` 出图。要用 `StreamMark.Avalonia` 的 `internal` 成员（如 `SegmentLayout.LineCount`、`TextSegmentView.ShowViewer`）不用额外声明——`src/StreamMark.Avalonia/Images/AssemblyInfo.cs:3` 那一条已经覆盖整个程序集；但**引用可选子包**的 internal 类型（`MermaidThemer`、`DiagramKind`、`CssColorResolver`、`TextMateHighlightSession`）仍只靠各包自己的 `InternalsVisibleTo`（Mermaid `:24`、TextMate `:14`），RaTeX 包没有、只能用公开类型（`Assert.IsType<RaTeXMathLayout>`）。漏掉会被编译期可访问性报错挡住（不是运行时症状）。

- **加一条性能上限断言**：参考 `LongCodeTests` 的写法——先 warm-up，再取 `Skip(1).Order()` 后比较中位数与最大值，并用 `Environment.GetEnvironmentVariable("CI")` 放宽阈值（`tests/StreamMark.Avalonia.Tests/Transcript/LongCodeTests.cs:54`、`:57-58`）。只断言最大值会在共享 CI 机器上偶发失败。`IncrementalLayoutTests.AppendCost_DoesNotGrowWithParagraphLength` 用的是同一套路（比值 + 常数余量，`:106`）。
- **加一条字体断言**：不要用 `FamilyTypefaces` 列表推断系统有没有更粗的字面，也不要为了判断去 `new Typeface(...).GlyphTypeface` 探测（会触发合成并污染 Avalonia 的字体缓存，让后面的测试拿到合成字形）。按"已经解析出来的 run"判断，并给出平台豁免（`tests/StreamMark.Avalonia.Tests/Rendering/InlineStyleProbeTests.cs:35-44`）。

## Invariants and traps
- **无头测试必须走 `HeadlessApp.Run` + `Settle`**：`Run` 用 `Dispatch(async () => { await body(); return true; }, ...)` 强制走 `Func<Task<bool>>` 重载，从而真正等测试体结束 — `tests/StreamMark.Avalonia.Tests/HeadlessApp.cs:57-61`。把 async lambda 直接交给 `Dispatch` 会被当成 `Func<TResult>`（返回的是未完成的 `Task`，外层立刻返回），测试提前绿。
