# Avalonia 块视图与文本自绘层

把 Core 的块模型与文档快照画成 Avalonia 控件：每个顶层块一个自绘 `BlockView`，每个文本片段一个 `SegmentLayout`（**逐行** `TextLine`，流式追加只从差异点所在行的**前一行**重排，之前的行对象与已录制内容不动；行内样式走自定义 `ITextSource`，公式 / 图片 / 复选框是 `DrawableTextRun`），`DocumentPresenter` 按快照差异增删改这些视图，末尾渐显在**渲染线程**的自定义视觉上完成，主题色由 `MarkdownStyle` 一次性解析成资源快照下发。

**不负责：** Markdown 解析与块模型（`core-parsing-and-model`，`src/StreamMark.Core/Model/`、`src/StreamMark.Core/Parsing/`）；文档快照与差异算法（`core-streaming`，`src/StreamMark.Core/Streaming/SnapshotDiff.cs:SnapshotDiff.Compute`）；选区坐标、命中与复制、**查找模型**（`avalonia-selection`，`src/StreamMark.Avalonia/Selection/`，含 `SelectionModel` / `SearchModel`——本层只在 `Render` 里消费它们的区间并画矩形）；会话虚拟化与行回收（`avalonia-transcript`，`src/StreamMark.Avalonia/Transcript/TranscriptPanel.cs`）；图片的取数 / 解码 / 缓存（`avalonia-images`，`src/StreamMark.Avalonia/Images/ImagePipeline.cs`，本层只用 `Rendering/ImageSlot.cs` 持有句柄）；插件注册与块视图注册表（`avalonia-plugin-system`，`src/StreamMark.Avalonia/Plugins/PluginRegistry.cs`）；RaTeX / TextMate / Mermaid 的具体实现（`avalonia-extensions`）与 `Md.*` 资源键的宿主覆盖（`theme-and-styles`，含 AtomUI 令牌主题）。

## How to extend
- To add 新的块视图（新块类型或新的内建渲染方式）：先在 `BlockViewFactory.ViewTypeFor`（`BlockViewFactory.cs:91`）加分支并在 `CreateBuiltIn`（:22）映射到新视图类，再在 `CanReuseBuiltIn`（:56）加 `view switch` 分支（用于复用 / 类型切换），最后按 `BlockView`（`BlockView.cs:13`）实现 `OnUpdate` / `MeasureOverride` / `ArrangeOverride` / `Render`，容器类视图继承 `StackBlockView`（:63）复用 `UpdateChildren`。漏掉 `CanReuseBuiltIn` 的后果：`CanReuse` 落到 `_ => false`，每次快照更新都重建视图——输入焦点、块状态与滚动位置丢失（`BlockStateStore` 只能保住 `Get/Set` 过的东西），并且 `DocumentPresenter.Restyle` 每帧替换全部视图。若新块类型要参与选区，还要同步 `Selection/BlockText.Segments` 的遍历分支与其顺序一致。

## Invariants and traps
- 逐行排版必须与整段排版**逐行一致**，所以重排起点是**差异点所在行的前一行**，不是差异点所在行 — 行首本身是断行机会，但禁则（如行首不能是句号）会把前一行的末字拉到下一行；末尾空行（硬换行之后）要回退到产生它的那一行 — see `src/StreamMark.Avalonia/Rendering/SegmentLayout.cs:64`（`LineIndexOf(from) - 1`）、`:66`；回归测试 `IncrementalLayoutTests`。
- `TextRunCache` 的 `InvalidateFrom(i)` 必须传入**差异点所在段落的起点**，不是差异点本身 — 缓存以换行符分隔的段落为单位、按段落起点存放整段的整形结果，从差异点失效会复用旧段落（连同段末换行），表现是每次追加都变成一次硬换行；当前逐行重排路径不传缓存（`SegmentLayout.cs:86` 的 `restart == 0 ? cache : null`），缓存只在整段重排（宽度 / 对齐变化）时生效，但失效规则不变 — see `src/StreamMark.Avalonia/Rendering/TextSegmentView.cs:199`；回归测试 `Transcript/SmoothStreamWrapTests.cs:15`。
- `TextRunCache` 是 Avalonia 12 的 `[Unstable]` 预览 API — 只允许在 `TextSegmentView` 与 `SegmentLayout` 内使用，并用 `#pragma warning disable CS0618` 限定范围（`TextSegmentView.cs:38`、`SegmentLayout.cs:140`）；换别的文件用要重新评估（同一快照里 `TextLayout` 也是预览重载）。
- 渐显的不透明度只在**渲染线程**算 — 界面线程只在排版 / 末尾状态变化时下发一次 `FadeFrame`（`TailFade.Update` :27），`FadeHandler.OnRender`（:306）按 `StreamClock.Now` 逐帧算不透明度，且只在 `now - newest < FadeDuration` 期间继续 `RegisterForNextAnimationFrameUpdate`（:293-304）。**不要**在界面线程加每帧 `RequestAnimationFrame` → `InvalidateVisual` 的循环来重画渐显（旧做法，被 `docs/decisions.md` 的「流式渲染的 CPU」否决）— see `src/StreamMark.Avalonia/Rendering/TailFade.cs:275`。
- 渐显层（渲染线程）只能画字形与矩形：内嵌对象、带装饰线（链接下划线）或 RTL 的文字段不参与渐显，渐显起点移到其后（`TailFade.SkipUnfadeable` :193 / `Fadeable` :216）；行视觉的矩形裁剪（`SegmentLineVisual.ClipRight`）与渐显层的批次矩形必须在同一横坐标衔接，改其中一边要同步另一边 — see `src/StreamMark.Avalonia/Rendering/TailFade.cs:121-141`、`src/StreamMark.Avalonia/Rendering/TextSegmentView.cs:396`。
- 回退字体必须与取 run 的起点和匹配历史无关 — 逐行排版从行首重新取 run，所以 `CreateCharacters`（:1037）按整段缺字文字的第一个字（向前找到 span / 内嵌对象边界或主字体能覆盖的字为止）匹配回退字体，而不是按行首的字（Windows 上"。"与"首"可能匹配到不同字体）；Avalonia 的 `TryMatchCharacter` 又会优先复用之前匹配到的字体，所以 `MatchFallback`（:1088）用静态字典记住每个字第一次的结果。任何一处依赖起点或历史，流式结果都会与整段排版不同（背景与修复见 `.agents/memory/fallback-font-position-history.md`；回归测试 `IncrementalLayoutTests.StreamedMixedScripts_MatchFullLayout`）— see `src/StreamMark.Avalonia/Rendering/TextSegmentView.cs:1031-1090`。
- 回退字体只用字体族里**真实存在**的字面 — 不能用 `Typeface(…, 字重).GlyphTypeface` 去试探不存在的字重 / 字形：Avalonia 12 会合成粗体 / 斜体，合成时把整份字体文件复制三份常驻内存（Apple Color Emoji 约 600MB）；`RealFace`（:1123）只在 `FontFamily.FamilyTypefaces` 里选（粗体取离请求最近的不低于 600 的字重，其次最粗的 ≥500，再没有就用常规），**回退字体一律用正体，不请求斜体**：Windows 上按字重拆开的族（"Yu Gothic UI Semibold"）的 `FamilyTypefaces` 会列出并不存在的斜体面，请求它会让 Avalonia 取同族已缓存的最近字面合成斜体并缓存在这个族里（连正体请求也可能取到它），而且事后加载检查本身就会创建这份合成字面，所以只能不请求。表格的粗体中文表头会先把该族缓存好，回归测试因此要在暖缓存下跑。回归测试 `InlineStyleProbeTests.FallbackRuns_UseRealFaces_NotSyntheticCopies`。
- 删除线自绘，不用 `TextDecorations.Strikethrough` — 部分字体（含无头环境的回退字体）缺少删除线度量，装饰线不显示；`DrawStrikethrough`（:600）按每段 `HitTestTextRange` 在 54% 高度画线，且必须画在**行视觉**里（每行只画落在本行内的 span）。
- 只有文档末尾片段（`IsDocumentTail`，由 `DocumentPresenter.UpdateTail` :102 或 `TranscriptPanel.UpdateTail` :984 设置）才渐显并绘制光标（`TextSegmentView.cs:591`）— 片段不再是末尾时，已开始的渐显由 `TailFade` 的定时器在结束后清理；`UpdateTail` 每次 `Apply` 对尾部 `InvalidateVisual()` 只重录片段自身的小块绘制（光标在流结束后消失靠它）。
- 片段的命中测试靠 `Render` 里的透明矩形（`TextSegmentView.cs:573`）：行视觉不是输入元素，命中测试会跳过它们及其子树；去掉透明矩形会让链接、图片点击与选区落点失效。
- 固定行高会把整行裁到该高度 — 行内有更高的对象（图片、大公式）时 `SegmentLayout` 只把这一行用自然行高重新排版 — see `src/StreamMark.Avalonia/Rendering/SegmentLayout.cs:108`（`Overflows` :155）。
- 上下文（`RenderContext`）的身份就是"变化"信号 — 样式 / 服务 / 主题变化必须**新建** `RenderContext` 实例（`MarkdownView.CreateContext` :172），`BlockView.Update` 与 `TextSegmentView.Set` 都靠 `ReferenceEquals` 判断 `contextChanged`（`BlockView.cs:27`、`TextSegmentView.cs:166`）；原地修改样式对象不会触发任何重排或 `Restyle`。
- 片段编号必须在构建期按阅读顺序分配，并与 `BlockText.Segments` 的遍历顺序一致 — 选区坐标是 `(Entry, BlockKey, Segment, Offset)`（`Selection/TextPoint.cs:8`），顺序错位会造成选区串段；`KeyFor` 每次调用都会 `segment++`（`BlockView.cs:45`），因此目标块类型变化（例如代码块 → 图表）时不能"两边都先建 key 再选分支"；折叠块标题这类不参与选区的片段用负数编号（`BuiltInComponentsPlugin.cs:76`）。
- 查找高亮在 `Render` 里画在文字**下方**，按 `SelectionModel.GetHighlights(Key, 长度)` 取区间，当前结果用 `SearchCurrentBackground`、其余用 `SearchHighlightBackground` — 三处视图各画一遍（`TextSegmentView.cs:575`、`CodeBlockView.cs:644`、`DiffBlockView.cs:817`），新增会显示文字的视图要自己加这一段，否则查找结果在它上面不可见。
- `BlockOverlay` 里的副本用**独立的** `SelectionModel`，但片段编号必须与文档中相同 — 它把原上下文复制成 `new RenderContext(..., new SelectionModel(), ...)` 后按同一个块模型 `Update`（`BlockOverlay.cs:47-49`）；覆盖层副本的 `TableBlockView.IsInOverlay`（`TableBlockView.cs:236`）防止再套一层全屏。
- 代码块分段的横向滚动各自独立（已知限制）— `CodeTextView._offsetX` 是每个视图自己的状态，`SetChunk`（`CodeBlockView.cs:94`）只切窗口不共享偏移。
- `CodeBlockState` 只在界面线程访问（`BlockStateStore` 的约定），后台 `RunHighlight` 回投时必须校验 `ReferenceEquals(session, _session)`，否则重建后的块会收到过期着色 — see `src/StreamMark.Avalonia/Rendering/CodeBlockState.cs:142`。
- 图片句柄是借用关系：`ReleaseUnusedImages` 只在 `_fullRebuild`（或关缓存）时执行（`TextSegmentView.cs:354`、`:532`），部分复用缓存的排版不释放，离开可视树则全部 `Dispose` 并重排（:268）。
- 代码块的 `CodeTextView` 是"整个代码块"的选区片段，`Segments()` 只返回它（`CodeBlockView.cs:403`）；`DiffBlockView` 同理只返回 `_body`（`DiffBlockView.cs:202`，显示单元格再映射回原始行）；`DiagramBlockView` 显示图表时 `Segments()` 返回空（图表不可选，`DiagramBlockView.cs:358`）。
- 标题级别必须随块类型复位 — `TextBlockView` 在 `HeadingBlock` 分支写级别、在 `ParagraphBlock` 分支写回 0（`BlockView.cs:180` / `:185`），否则读屏会把后来的段落当成上一级标题。
