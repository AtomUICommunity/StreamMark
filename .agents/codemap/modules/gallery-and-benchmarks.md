# 示例程序与基准

`samples/StreamMark.Gallery` 是一个 Avalonia 桌面演示程序（2026-10-19 起是 Markdown 编辑器）：「编辑器」页左侧大纲、中间 AvaloniaEdit 源码编辑器、右侧 StreamMark 实时预览，「会话演示」页保留原来的会话视图与模拟流式回答；同时它也是仓库唯一的 NativeAOT 冒烟测试（`--smoke` 分支，靠退出码当门禁），并由 `.github/workflows/release-gallery.yml` 以 GitHub 预发布的形式分发。能力清单与计划在 `docs/gallery.md`。`bench/StreamMark.Benchmarks` 是独立的 BenchmarkDotNet 项目，只做“整篇重解析 vs StreamMark 冻结前缀”和 58k 尾部 remend 两组对比。第二个基准项目 `bench/StreamMark.CpuHarness` 不是 BenchmarkDotNet：它是一个**真实窗口**的 NativeAOT CPU 采集器，由 `tools/cpu-bench.sh` 按场景矩阵启动，每场景输出一行进程 / 界面线程 CPU、分配速率与 GC 统计，追加到 `artifacts/cpu-bench.txt`，数字记录在 `docs/benchmarks.md` 的「流式 CPU」一节（`docs/benchmarks.md:50`）。
**不负责：** 渲染控件与插件系统本身（`avalonia-plugin-system`、`avalonia-text-rendering`、`avalonia-transcript`），流式引擎与节奏控制（`core-streaming`），AOT 发布参数 / IL 警告门禁 / CI 任务编排（`build-and-packaging`，`.github/workflows/ci.yml`），原生库怎么编与怎么被复制到输出目录（`native-ratex`、`Directory.Build.targets`），记录下来的实测数字（`docs/benchmarks.md`）。

## Contracts it exposes
- **`--smoke` 的语义**：命令行里出现 `--smoke` 就完全不启动 UI 生命周期，改为跑检查并返回退出码（`samples/StreamMark.Gallery/Program.cs:16`）。`0` = 全部 PASS，`1` = 至少一项 FAIL；失败明细以 `FAIL <name> — <detail>` 打在 stdout。正常启动时，非 `--` 开头的现存文件路径会被打开（`samples/StreamMark.Gallery/App.axaml.cs:21`）。
- **它验证哪些子系统**（全部在 `SmokeTest.Run` 内）：
  - 原生 RaTeX 调用能否成功、能否报错：`ratex.layout`（`SmokeTest.cs:37`）、`ratex.error`（`:40`）—— 覆盖“原生库不在二进制旁”这类打包事故。
  - 编辑命令（纯函数，不需要界面）：`editor.*` 共 21 项，覆盖包裹 / 取消包裹、占位选区、标题、列表前缀、链接、列表续写与退出、缩进、块插入、字数统计（`SmokeTest.CheckEditorCommands`，`:84`）。
  - 编辑器页（无头渲染）：`ui.editor.preview`（预览快照与编辑器文本同长）、`ui.editor.code` / `ui.editor.diff`、`ui.editor.outline`、`ui.editor.highlight`（TextMate 行变换器已装）、`ui.editor.edit` + `ui.editor.reuse`（中间插表后第一个块视图仍是同一实例）、`ui.editor.sync`（编辑器滚到「差异」后预览偏移 > 100）、`ui.editor.undo`（撤销到原始状态不再是已修改）、`ui.editor.replay`、`ui.editor.viewmode`。
  - Core 的 AOT 路径：`stream.complete` / `stream.blocks` / `stream.diff`（`:60-62`），用 `StreamPacer` → `StreamingDocument` → `SnapshotDiff` 跑一遍 5 块的 markdown（`:40`），并断言 `final.Count == 5`、第 1 块的行内对象数、代码块语言、表格块类型。
  - 界面渲染：`ui.stream.complete`（`:95`）、`ui.virtualized`（`:110`，断言 `RealizedCount > 0 && RealizedCount < RowCount`）、`ui.math`（`:111`）、`ui.diagram`（`:112`，必须 `IsShowingDiagram` 且高度 > 80）、`ui.code`（`:113`）、`ui.components`（`:114`，`CollapsibleBlockView` 即 `showcase.md` 的 `<details>`）、`ui.html`（`:115`，`HtmlBoxBlockView` 至少 2 个）、`ui.frame`（`:118`，能取到渲染帧）。这段整体包在 try/catch 里，异常转成一条 `ui.render` FAIL（`:69-72`）。
  - 未知参数、多余参数一律忽略，不会报错。
- **基准的参数与 filter 用法**：入口只是 `BenchmarkSwitcher.Run(args)`（`bench/StreamMark.Benchmarks/Program.cs:3`），因此 `--filter '*'`（跑全部类）、`--job short`（ShortRun，少迭代）、`--exporters github`（CI 用）都是 BenchmarkDotNet 自己的开关，本模块不解析。类名可作 filter：`--filter *StreamingBenchmarks*` / `--filter *RemendBenchmarks*`。项目设了 `OutputType=Exe` + `Optimize=true`（`bench/StreamMark.Benchmarks/StreamMark.Benchmarks.csproj:3`、`:5`），但**必须 `-c Release`**（`docs/benchmarks.md:3`、`.github/workflows/ci.yml:133`）。
- **CPU 采集器的场景矩阵与语义**（全部写在 `tools/cpu-bench.sh:15-22`）：`idle`（`SM_IDLE=1 SM_SECONDS=6`）、`chat`、`chat-nofade`（`SM_FADE_MS=0`）、`chat-nosmooth`（`SM_SMOOTH=0`）、`chat-region`（`SM_REGION=1`）、`long-paragraph` / `long-para-nofade` / `long-code`（三者用 `SM_SAMPLE` 指到 `Samples/` 下的文件）。每行字段含义见 `bench/StreamMark.CpuHarness/Program.cs:162-163`：`cpu=` 是**进程 CPU 占一个核心的百分比**（不是全机、也不是多核合计），`ui=` 是界面线程占比，`other=` 是两者之差，后面跟 `alloc` MB/s、`gc0` 次数、`gcpause` 毫秒与耗时前 6 的线程。`tools/cpu-bench.sh:13` 每次运行先追加一行 `# <UTC 时间> <rid> <短 SHA>` 作表头，所以同一个文件里可以累积多次运行的对照。
- **CPU 采集器只能以 NativeAOT 发布产物运行**：脚本第 8 行固定 `dotnet publish -c Release -r $rid`，`Program.cs:22` 的注释写明 JIT 构建的结果含后台编译、不可比。脚本用 `grep -E "warning IL|error" || true` 过滤发布日志（`tools/cpu-bench.sh:8`）——**这只是把 IL 警告与错误回显到终端，`|| true` 让脚本即使命中也不失败**，所以它不构成 AOT 门禁，门禁仍在 `.github/workflows/ci.yml:112` 的 Gallery 发布上。
- **嵌入资源命名约定**：`LogicalName` 由 `%(Filename)%(Extension)` 生成并加 `Samples.` 前缀（`samples/StreamMark.Gallery/StreamMark.Gallery.csproj:15`），所以从代码读的名字永远是 `"<文件名含扩展名>"`。新增示例 markdown **不需要改 csproj**（通配 `Samples\*.md`），但**必须**在调用处用同名参数（`Program.Sample("新名字.md")`）。

## How to extend
- **新增一个示例文档**：把 `xxx.md` 丢进 `samples/StreamMark.Gallery/Samples/`（csproj 是通配的），再往 `EditorPage.SampleList`（`samples/StreamMark.Gallery/Editor/EditorPage.cs:35`）加一行 `("xxx.md", "标题")`，「示例」菜单就会出现它。**漏掉第二步 → 文档嵌进去了但菜单里没有。**改名时必须同步 `SampleList` / `Program.Sample` 的参数字符串，否则 `GetManifestResourceStream` 返回 null 直接抛 `InvalidOperationException`。
- **新增一个格式化命令**：在 `MarkdownCommands` 加纯函数（输入源码与选区，返回 `TextEdit`），在 `EditorPage` 加一个调用 `Run(...)` 的方法并挂到工具栏（`CreateToolbar`）和 / 或 `OnPageKeyDown` 的快捷键表；在 `SmokeTest.CheckEditorCommands` 补一条 `Expect`。改快捷键要同步 `Samples/welcome.md` 的快捷键表。
- **新增一项基准**：在 `bench/StreamMark.Benchmarks/StreamingBenchmarks.cs`（或同项目下新文件）加一个带 `[MemoryDiagnoser]` / `[Benchmark]` 的类，用 `[GlobalSetup]` 现场造输入（照 `StreamingBenchmarks.Setup`）。要对比就加 `Baseline = true`（`:21`）与 `Description`；需要 Core 的 internal 类型（如 `DocumentComposer`）已由 `src/StreamMark.Core/StreamMark.Core.csproj:10` 放行。**漏掉 `[GlobalSetup]` 建输入 → 基准跑在空字符串上，得出“零耗时”的假结论**；**漏掉 `-c Release` → 结果是无意义的 Debug 数字**。不需要注册到任何列表，`--filter '*'` 会自动发现新类。
- **给 CPU 采集器加一个场景**：改 `tools/cpu-bench.sh:15-22` 的 `run` 行（`run <label> env SM_XXX=…`），环境变量本身在 `bench/StreamMark.CpuHarness/Program.cs:24-30` 的 `<remarks>` 里有清单，新加开关时**同一次改动里补上那段注释**——它是唯一的变量文档。需要新样例就丢进 `bench/StreamMark.CpuHarness/Samples/` 并用 `SM_SAMPLE` 传绝对路径（脚本用的是 `"$PWD/$samples/..."`，`:20`）；只有当样例要作为**默认**输入时才需要改 csproj 的 `EmbeddedResource`（`bench/StreamMark.CpuHarness/StreamMark.CpuHarness.csproj:20`，当前只嵌 `chat.md`）。**漏掉 `run` 行 → 变量存在但没人设，量到的是默认场景的重复**；**改动渲染 / 排版 / 节奏 / 会话面板后应重跑一次并与 `docs/benchmarks.md:50` 的「流式 CPU」表对照**（`AGENTS.md:23`），但不要把结果当 CI 门禁。
- **给 CPU 采集器加一个开关要注意 Windows**：`ThreadCpu.Now` 在 Windows 上恒返回 0（`bench/StreamMark.CpuHarness/Program.cs:251-254`），任何以 `ui=` 差值为依据的新断言在 Windows 上都得不到有效数字。
- **给冒烟测试增加一项检查**：在 `SmokeTest.Run` 里调 `Check("<名字>", <条件>, <detail>)`；会话页的界面检查放进 `RenderChat`，编辑器页的放进 `RenderEditor`（`samples/StreamMark.Gallery/SmokeTest.cs:146`、`:180`）。**依赖时间/渲染的断言必须放在 `Pump()` 等待循环之后**，否则检查会在视图树建好之前执行，表现为随机 FAIL；查找视图时限定在 `window.Chat` 或 `editor.Preview` 的后代里，两页同时在视觉树里。新增检查会拉高“冒烟通过”所要求的渲染能力，任何一项 FAIL 都会让 CI 的 `aot-smoke` 与 release 的 `gallery` 任务红。
- **给演示加一个插件**：只在 `Program.CreateServices` 的 `Plugins` 列表里加（`samples/StreamMark.Gallery/Program.cs:43-53`）；两页共用窗口上的 `MarkdownServices`，编辑器页每个文档都用 `services.Profile` 创建（`EditorPage.LoadText`），会话页用 `ChatPage` 构造参数里的 `profile`。
- **让冒烟覆盖新的原生 / AOT 风险点**：直接在 `SmokeTest.Run` 里加一段调用 + `Check`，不要再建一个 `--smoke-xxx` 参数——CI 只认 `--smoke` 一个开关（`.github/workflows/ci.yml:121`）。

## Invariants and traps
- **Gallery 是 NativeAOT 发布目标**：`PublishAot=true` 写在示例项目里（`samples/StreamMark.Gallery/StreamMark.Gallery.csproj:7`，注释 `:6` 说明它“兼作冒烟测试”），所以这个模块里的任何代码都在裁剪 / AOT 分析之下，`IL2026` 一类诊断已是错误（`Directory.Build.props:14`）。示例里能用 `new Random(7)` / 反射式的嵌入资源读取，是因为 `GetManifestResourceStream` 与其它写法已被验证干净；**在演示代码里随手引入反射或动态代码会直接打断 CI 构建** — see `samples/StreamMark.Gallery/StreamMark.Gallery.csproj:PublishAot`。
- **CI 要求 0 个 IL 警告，用日志 grep 卡，不靠 MSBuild 属性**：`dotnet publish samples/StreamMark.Gallery -c Release -r <rid> -o artifacts/aot` 的输出被 `tee` 到 `publish.log`，然后 `grep -E "warning IL[0-9]+" publish.log` 命中即 `::error::` + `exit 1`（`.github/workflows/ci.yml:111-114`）。加代码后本地应照这条命令自查 — see `.github/workflows/ci.yml:aot-smoke`。
- **`--smoke` 的退出码就是门禁**：CI 最后一步是 `./artifacts/aot/StreamMark.Gallery --smoke`，非零即任务失败（`.github/workflows/ci.yml:121`）。`SmokeTest.Run` 只有在 `failures == 0` 时返回 0（`samples/StreamMark.Gallery/SmokeTest.cs:75`），所以**任何一条 `Check` 变红都会挡住发布**；反过来说，往 `Check` 里塞了恒真的条件就等于没测 — see `samples/StreamMark.Gallery/SmokeTest.cs:Run`。
- **冒烟运行需要把原生库复制到二进制旁边**：`RaTeXEngine.Layout` 会 P/Invoke 原生库（`src/StreamMark.RaTeX/RaTeXEngine.cs:22`），所以 publish 后有专门一步 `cp artifacts/native/<rid>/* artifacts/aot/`（`.github/workflows/ci.yml:116-118`），而不是指望 publish 自己带上。本地等价做法是 `dotnet publish` 到项目默认 publish 目录（`README.md:109`），或先跑 `native/build.sh` 让 `Directory.Build.targets:13` 的复制项生效。**漏掉这一步 → 冒烟在 `ratex.layout` 那条就 FAIL（原生库加载失败），而不是给出有用的错误** — see `.github/workflows/ci.yml:Copy native library next to the binary`。
- **冒烟测试必须能在无头 / 无窗口环境跑完**：它不依赖 `Program.BuildAvaloniaApp`（那个用 `UsePlatformDetect()`，在 CI runner 上没有显示服务），而是在 `RenderGallery` 里自建 `AppBuilder.Configure<GalleryApp>().UseSkia().UseHarfBuzz().UseHeadless(new AvaloniaHeadlessPlatformOptions { UseHeadlessDrawing = false })`（`samples/StreamMark.Gallery/SmokeTest.cs:123-127`）。`UseHeadlessDrawing = false` 是必须的，否则 `CaptureRenderedFrame()` 拿不到帧、`ui.frame` 会 FAIL（`:117-118`）。窗口先被硬调成 `1000×2400`（`:130`）就是为了让虚拟化仍然生效（`ui.virtualized` 断言 `RealizedCount < RowCount`，`:110`）——**把高度改成能装下全部内容的值会让这条断言失去意义** — see `samples/StreamMark.Gallery/SmokeTest.cs:RenderGallery`。
- **等待循环有 30 秒死线**：`RenderChat` 与 `RenderEditor` 各自 `deadline = DateTime.UtcNow.AddSeconds(30)`（`samples/StreamMark.Gallery/SmokeTest.cs:151`、`:186`），各自被流等待 / 图表等待 / 预览等待共用。超时不会抛异常，只会让后面的检查以 FAIL 收场；`Pump()` 里带 `Thread.Sleep(16)`，所以整段是真实时间驱动的 — see `samples/StreamMark.Gallery/SmokeTest.cs:Pump`。编辑器部分把窗口改成 900 高（`:183`），否则编辑器与预览都不需要滚动、`ui.editor.sync` 失去意义。
- **流谓词断言靠固定种子**：模拟分片用 `new Random(7)`（`samples/StreamMark.Gallery/Chat/ChatPage.cs:56`、`EditorPage.ReplayAsync`），冒烟里又断言 `final.Count == 5` 与具体块类型（`samples/StreamMark.Gallery/SmokeTest.cs:64`，那段用的是内联 markdown，与示例文件无关）。
- **演示窗口与冒烟窗口共用 `MainWindow`，构造即建服务**：`MainWindow` 构造函数里就 `CreateServices()` 并 `SetServices`（`samples/StreamMark.Gallery/MainWindow.cs:33-34`），`TextMatePlugin` 还带 5 个语法的 `prewarm`。冒烟里 `SetupWithoutStarting()` 是进程级一次性操作，**重复配置 `AppBuilder` 或重复构造窗口会撞上已初始化的 Avalonia 单例** — see `samples/StreamMark.Gallery/SmokeTest.cs:RenderGallery`。
- **编辑器预览不能用 `MarkdownView.Markdown`**：给它赋值会 `_presenter.Clear()` 清空全部块视图（`src/StreamMark.Avalonia/MarkdownView.cs:103-120`），逐键输入就整篇重建；`EditorPage` 改用 `Document` + `StreamingDocument.Load`，并在换文件时换新文档（清空按偏移记录的块状态）。详见记忆 `editor-preview-document-path`。
- **AvaloniaEdit 的样式只能在 XAML 里引入**：代码里 `new StyleInclude(uri)` 是 `RequiresUnreferencedCode`，会产生 IL2026 让 AOT 门禁失败；它在 `samples/StreamMark.Gallery/App.axaml:10`。**AvaloniaEdit 12 的 `TextEditor.ScrollToVerticalOffset` 是空实现**，滚动编辑器要用 `ScrollTo(line, 0, VisualYPosition.LineTop, 偏移, 0)`（`EditorPage.JumpTo`、`SmokeTest.RenderEditor`）。
- **本地图片默认被拦**：`ImagePolicy.AllowedFileRoots` 默认为空，`EditorPage.SetImageRoot` 只放行当前文件所在目录；未保存的新文档没有放行目录，相对路径图片不显示。
- **基准只记录量级，不能当性能门禁**：项目没有阈值断言，`docs/benchmarks.md:3` 用的就是 `--job short`（ShortRun），记录里 `Full reparse per token` 的 Error 达到 1,197 ms、`Heal58kTail` 的 Error 347 µs，误差与均值同量级（`BenchmarkDotNet.Artifacts/results/StreamMark.Benchmarks.StreamingBenchmarks-report-github.md`、`...RemendBenchmarks-report-github.md`）。**别用单次结果判断回归，也别把 bench 接进 CI 的必要路径**——CI 里它只在 `workflow_dispatch && inputs.bench` 时跑（`.github/workflows/ci.yml:124`） — see `docs/benchmarks.md:ShortRun`。
- **`docs/benchmarks.md` 里的视图层与扩展数字不是 BenchmarkDotNet 项目产出的**：视图层数字来自无头测试 `VirtualizationScaleTests`（`docs/benchmarks.md:26`、`:43`），扩展数字标着“NativeAOT，子代理实测”（`:34`），而 `bench/StreamMark.Benchmarks` 只引用 Core、根本看不到 UI 类型（`bench/StreamMark.Benchmarks/StreamMark.Benchmarks.csproj:11`）。想让 BenchmarkDotNet 覆盖渲染层，得先解决这个引用缺口 — see `bench/StreamMark.Benchmarks/StreamMark.Benchmarks.csproj:ProjectReference`；渲染层的**真实窗口**数字走的是另一条路（`bench/StreamMark.CpuHarness` + `tools/cpu-bench.sh`），它不经过 BenchmarkDotNet。
- **CPU 采集器的数字是量级与占核百分比，不是 CI 门禁**：`docs/benchmarks.md:52` 明确写了环境（MacBook Air M 系列、2560×1600、Metal、10 条历史消息、320 字/秒、预热 3 秒后统计 12 秒）与“进程 CPU 占一个核心的百分比，误差约 ±1.5”，表里还留有“改前 / 改后”两列 alpha.15 → alpha.16 的对照（`:54-62`）。采集器自身**不做任何阈值判断**，`RunAsync` 只是打印一行并写文件（`bench/StreamMark.CpuHarness/Program.cs:162-168`），`tools/cpu-bench.sh` 也不比较基线，且要真的开窗（`Program.cs:35`、`tools/cpu-bench.sh:3` 要求“保持窗口可见”）。**别把它接进 CI 的必要路径，也别用单次结果判断回归。**

## Tests
- 本模块**没有单元测试**：`samples/` 与 `bench/` 下没有测试工程，`dotnet test StreamMark.slnx` 不会触及它们（`StreamMark.slnx:14-20` 里 `bench/` 的 2 个与 `samples/` 的 1 个只作为项目列出）。
- `--smoke` 就是本模块的测试：CI 的 `aot-smoke` 任务在 `linux-x64` / `osx-arm64` / `win-x64` 三个 RID 上 `dotnet publish` → grep IL 警告 → 复制原生库 → `./artifacts/aot/StreamMark.Gallery --smoke`（`.github/workflows/ci.yml:87-121`）。本地等价：`dotnet publish samples/StreamMark.Gallery -c Release -r <rid>` 后运行 publish 目录里的二进制并加 `--smoke`（`README.md:109`）；想留一张渲染图就再加 `--out=<path.png>`（`samples/StreamMark.Gallery/SmokeTest.cs:119`）。
