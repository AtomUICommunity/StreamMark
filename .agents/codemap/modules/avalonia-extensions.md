# avalonia-extensions（三个渲染扩展包：TextMate 代码高亮 / RaTeX 公式 / Mermaid 图表）

三个独立的可选包，各自实现一个渲染接口（高亮是 Core 的 `ISyntaxHighlighter`，公式与图表是 `StreamMark.Avalonia` 的 `IMathRenderer` / `IDiagramRenderer`）并用一个 `IMarkdownPlugin` 把它注册进 `MarkdownPluginBuilder`：TextMate 包用 TextMateSharp 按行增量着色；RaTeX 包把 LaTeX 经 C ABI 交给 Rust 引擎排版成显示列表、再在界面线程转成 Avalonia 图元；Mermaid 包用 Mermaider 出 SVG，按配色方案（默认复刻 mermaid.js 官方主题）重涂后把 `var()`/`color-mix()` 展开成字面颜色，再交给 Svg.Skia 变成 `SKPicture`。三者都不解析 Markdown，也不持有任何视图。包内还有两个与图表无关的宿主工具：`SvgImageRasterizer`（`ISvgRasterizer`）与 `WebPImageEncoder`（`IImageEncoder`）。

**不负责：** LaTeX / 围栏语法本身的解析与 `MathBlock` / `MathInline` / `CodeBlock` 节点的产生（`core-parsing-and-model`，`src/StreamMark.Core/Parsing/BackslashMathExtension.cs:15`、`MarkdigMapper.cs:20`）；代码块与公式块、图表块的视图（`avalonia-text-rendering`，`Rendering/CodeBlockView.cs`、`Rendering/MathBlockView.cs`、`Rendering/DiagramBlockView.cs`）——本模块只提供渲染器，**宿主视图负责把半透明主题色叠成不透明色后再传进来**（见「Contracts」）；插件的聚合与 `FindDiagramRenderer` 分派（`avalonia-plugin-system`，`Plugins/PluginRegistry.cs:46`）；图片获取 / 缓存 / 解码与缩略图落盘（`avalonia-images`，`Images/ImagePipeline.cs:62` 定义 `ISvgRasterizer`、`:55` 定义 `IImageEncoder`）；RaTeX 原生库的构建、交叉编译与 NuGet 打包（`native-ratex`，`native/ratex/**`、`native/patches/0001-enclose-border-uses-current-color.patch`、`native/build.sh`）。

## Contracts it exposes
- **`ISyntaxHighlighter` / `IHighlightSession`（Core 定义）**：`SupportsLanguage` / `CreateSession` / `GetThemeColors` 可任意线程并发调用（`TextMateSyntaxHighlighter.cs:10-16` 注释）；**单个会话只能在一个线程上顺序使用**（接口约定 `src/StreamMark.Core/Highlighting/ISyntaxHighlighter.cs:28`），实际调用方 `CodeBlockState` 用 `_highlightRunning` 保证同一会话同时只有一个 `Task.Run` 在使用它（`CodeBlockState.cs:105-116`）。`Update` 返回按 `'\n'` 切分的行数组，最后一行可以没有换行（`TextMateHighlighterTests.cs:167` 断言尾部换行会产生一个空末行）；`HighlightToken.Foreground == 0` 表示用默认前景色（`ISyntaxHighlighter.cs:16-18`，`ThemeContext.ResolveForegroundLocked` 在 colorId ≤ 1 时返回 0，`ThemeContext.cs:81-84`）。不认识的语言返回"每行空片段"的会话（`TextMateSyntaxHighlighter.cs:49-56`），且不加载语法（`TextMateHighlighterTests.cs:235` 断言 `TokenizedLineCount == 0`）。
- **语言别名表**：`LanguageAliases.Aliases` 是唯一权威表（`LanguageAliases.cs:11-84`），解析顺序是"表 → 按 language id → 按扩展名 `"." + name`"（`TextMateSyntaxHighlighter.cs:137-140`），`PlainNames` 里的名字在此前被拦掉，不走扩展名兜底（第 127-130 行，`LanguageAliases.cs:87`）。`Normalize` 兼容 `{.python}`、`python{1,3}`、`python title=x`、`language-python`、首尾空白与大小写（第 99-112 行）。
- **`IMathRenderer`（Avalonia 定义）**：`Layout` 必须线程安全（`Extensions/IMathRenderer.cs:7` 注释），**可在后台线程调用**；返回的 `MathLayout` 不可变、可跨线程共享，只有 `Draw` 必须在界面线程（`IMathRenderer.cs:33`，`RaTeXMathLayout.cs:10-12` 注释）。`Layout` 失败必须返回 `null` 并给出 `error`（流式中公式没写完属正常，`RaTeXMathRenderer.cs:47`）。
- **`IDiagramRenderer` / `DiagramResult`（Avalonia 定义）**：`RenderAsync` 可在后台线程执行，失败返回 `null`（界面回退为显示源码）；`DiagramResult.Draw` **必须在界面线程**，`Dispose` 后不得再画（`Extensions/IDiagramRenderer.cs:36,44,56,59`）。`MermaidDiagramRenderer.Render` 的约定是"不抛非取消异常"：内部 `try/catch` 后调 `ErrorReported` 并返回 `null`（`MermaidDiagramRenderer.cs:63-67,108-112`，回调异常也被吞，第 239-249 行），取消时抛 `OperationCanceledException`（第 52、59-62、69、104-107 行；已取消的 `RenderAsync` 直接 `Task.FromCanceled`，第 41-44 行）。
- **`DiagramRenderContext` 的颜色是"已定稿"的不透明色**（本模块最重要的一条对外契约）：`DiagramBlockView` 把 `Md.*` 里的半透明文字 / 代码底色沿可视树叠到块背后真实的底色上（`Rendering/DiagramBlockView.cs:124-168` 的 `ResolveEnvironment` / `BackdropColor`，`ColorOf` 第 254 行），**传给渲染器的 `Foreground` / `Background` / `Accent` 都是 `A == 255`**；`DiagramRenderContext` 的类注释（`Extensions/IDiagramRenderer.cs:6-9`）把这条约定写给了所有实现者。渲染器仍须自己兜底：`MermaidDiagramRenderer.CreateOptions` 对带透明度的输入走 `DiagramRenderContext.Flatten`（第 153-154、171 行），背景再叠一次到默认底色（`OpaqueBackground`，第 201-205 行），`Foreground.A == 0` 时按明暗取 #D4D4D4 / #27272A（第 155-158 行）。
- **`ISvgRasterizer`（avalonia-images 定义）**：在线程池上调用、必须线程安全（`Images/ImagePipeline.cs:61-68`）；实现返回 `null` 表示失败，`naturalSize` 为 SVG 的 `CullRect` 尺寸，放大受 `MaxDimension`（默认 4096）限制（`SvgImageRasterizer.cs:16,18-45`）。注意该实现**不做** `var()`/`color-mix()` 展开（只有 `MermaidDiagramRenderer.ResolveSvg` 那条路径做，`MermaidDiagramRenderer.cs:73,144`）。
- **`IImageEncoder`（avalonia-images 定义）**：同样在线程池上调用、必须线程安全，失败返回 `null`（该缩略图不落盘，`Images/ImagePipeline.cs:54-59`）。`WebPImageEncoder.Encode` 只接受 `Bgra8888` / `Rgba8888` 且 alpha 类型已知的位图，其余一律返回 `null`；像素经 `CopyPixels` 拷到非托管缓冲后交给 `SKPixmap.Encode`（`WebPImageEncoder.cs:19-57`）。
- **RaTeX 原生库加载与文件名约定**：`DllImport` 名是 `ratex_ffi`，由 .NET 按平台补前缀 / 后缀（`RaTeXNative.cs:8`）；实际产物在 `artifacts/native/<rid>/`，本机检出看到的是 `libratex_ffi.dylib`（osx-arm64 / osx-x64）、`libratex_ffi.so`（linux-x64 / linux-arm64）、`ratex_ffi.dll`（win-x64 / win-arm64）。项目引用方由根目录 `Directory.Build.targets:13` 按目标 RID 复制到输出目录；NuGet 使用方走 `runtimes/<rid>/native/`（`src/StreamMark.RaTeX/StreamMark.RaTeX.csproj:22`）。

## How to extend
- To add 一种代码语言 / 别名：先在 `LanguageAliases.Aliases` 里加"围栏名 → TextMateSharp language id"（`LanguageAliases.cs:11`，表里没有的名字会被当成 language id 或扩展名再去查一次，`TextMateSyntaxHighlighter.cs:140`）→ 再确认 `TextMateSharp.Grammars` 2.0.4 真的有这门语法（`Directory.Packages.props:18-19`）；能力边界写在 `docs/decisions.md:33`：**Kotlin 在 Grammars 包里不存在**，TOML 被有意映射到 INI（`LanguageAliases.cs:33`）→ 最后在宿主注册时预热，`new TextMatePlugin(prewarm: ["csharp", "rust"])`（`TextMatePlugin.cs:6,14`）或 `highlighter.PrewarmAsync(theme, …)`（`TextMateSyntaxHighlighter.cs:76`）。漏掉预热的症状是首个代码块首次 `Update` 卡数百毫秒（注释 `TextMateSyntaxHighlighter.cs:14-15`）；语言不存在时的症状是 `SupportsLanguage == false`，代码块按纯文本显示且完全不加载语法（`TextMateSyntaxHighlighter.cs:46-56`，测试 `TextMateHighlighterTests.cs:225` 用 `kotlin` 断言 false）。
- To add 一种图表语言：这一步**不需要改视图**——`BlockViewFactory` 只要 `FindDiagramRenderer(language)` 返回非空就把闭合的代码块换成 `DiagramBlockView`（`BlockViewFactory.cs:95`）。所以只要写一个 `IDiagramRenderer`（`CanRender` 认自己的语言名、`RenderAsync` 在后台跑、失败返回 `null`）→ `builder.AddDiagramRenderer(...)`（`Plugins/IMarkdownPlugin.cs:56`）→ 在宿主 `MarkdownServices { Plugins = [...] }` 注册（`README.md:33`）。漏掉注册的症状是代码块保持普通代码显示，不会有任何图表（`BlockViewFactory.cs:96`）；把 `CanRender` 写成大小写敏感会比较少见的围栏写法漏掉（Mermaid 自己做了 `Trim()` + `OrdinalIgnoreCase`，`MermaidDiagramRenderer.cs:33-34`）。若要改 Mermaid 的字体 / 字号，优先用 `MermaidDiagramRenderer.ConfigureOptions`（第 27 行）而不是改 `CreateOptions`（第 150 行）；它作用在配色方案映射**之后**（`BuildSvg` 第 132-135 行）。
- To add 一种公式语法 / 命令（例如新的 `\xxx`、新的字体）：C# 侧**不需要改**——能力全在原生引擎里，`RaTeXEngine.Layout` 只是通道（`RaTeXEngine.cs:22-52`）。只有当原生返回的显示列表出现**新的条目类型或字段**时才需要在 C# 侧配合：在 `DisplayList` / `DisplayItem` 加字段（`DisplayList.cs:18`）并在 `RaTeXMathLayout.BuildPlan` 的 `switch (item.Type)` 加分支（`RaTeXMathLayout.cs:102`）。漏掉分支的症状是静默不画——`BuildPlan` 没有 `default` 分支，未知 `Type` 被直接忽略（协议本身就允许忽略未来类型，`DisplayList.cs:20`）。若要新增宿主主题化的默认颜色语义，走哨兵色（`RaTeXMathLayout.cs:16`）而不是给每条图元染色。
- To add 主题 / 配色：Mermaid 只有三条路。① 换方案：`new MermaidDiagramRenderer { Theme = MermaidTheme.MermaidJsNeutral | Native }`（`MermaidTheme.cs:4`，`MermaidPlugin` 构造参数可以传进去，`README.md:51`）。② 细调宿主色映射：`ConfigureOptions`（`MermaidDiagramRenderer.cs:27`）。③ 新增一套固定配色：在 `MermaidPalette.For` 加分支 + 一个 `static readonly` 调色板（`MermaidPalette.cs:22,38-68`），颜色取自 mermaid.js 对应主题在流程图上的实际样式表，再确认 `MermaidThemer.Apply`（第 82 行）与 `PaintSvg`（第 119 行）两支都能把它表达出来 —— **只加调色板而不动这两处，子图与连线标签仍是 Mermaider 自己的涂法**。TextMate 走构造函数的两个主题名（`TextMateSyntaxHighlighter.cs:29`）。图表缓存键包含颜色与渲染器身份，换色会重画；渲染器自身的配置（`Theme`、`ConfigureOptions`）变化靠键里的渲染器身份区分，所以换配置要换渲染器实例（`DiagramBlockView.cs:117-118`）。

## Invariants and traps
- **TextMateSharp 2.0.4 不是线程安全的**：`Registry` 用普通 `Dictionary` 存语法、`Grammar` 分词时惰性编译规则并写内部表、主题匹配缓存也会在分词中被写入 —— 因此对 Registry / Grammar / Theme 的**每一次**访问都必须持有 `ThemeContext.Gate`（注释 `ThemeContext.cs:14-17`），落地在第 44 行的 `Gate`、`TextMateSyntaxHighlighter.cs:89-95` 的预热锁与 `TextMateHighlightSession.cs:97` 的会话锁。**每个主题各一把锁**（明暗互不阻塞），共享锁或去掉锁的表现是随机的颜色错乱 / 崩溃而不是异常。
- **高亮只重算"变了的地方之后"的行**：`Update` 用公共前缀决定保留哪些完整行（`TextMateHighlightSession.cs:59-66`），纯追加时原地截断 `_lines`（第 72-76 行）；非追加编辑分词到某个完整行的结束状态与旧缓存**相同**且该换行已落在公共后缀里时提前返回，余下行连同 token 数组整体复用（只平移偏移，第 145-159 行）。因此"中间改一行不影响语法状态"的编辑只重算 1-2 行（测试 `TextMateHighlighterTests.cs:337`），而"在第 1 行开块注释"必须重算后面全部（测试第 297 行）；一旦提前结束条件写错，症状是旧颜色粘在后面没跟着变。
- **超长行与超时是"局部退化"而不是失败**：行内容超过 4000 字符不着色且**保持传入的语法状态**（`TextMateHighlightSession.cs:167-169`）；单行 50ms 超时后用 1s 重试（第 181-187 行），仍超时则 `stoppedEarly` 为真、该行结束状态沿用上一行状态（第 196-197 行注释：与 VS Code 一致，避免把半截状态带到后续行）。`TokenizeLineResult2.StoppedEarly` 在 2.0.4 里是 `internal`，所以这里靠 `Stopwatch` 计时判断，误判只会多重试一次（第 241-245 行）。
- **主题默认前景色的 colorId 恒为 1**：`Theme.CreateFromRawTheme` 先解析主主题时第一个登记的颜色就是默认前景，于是未被规则命中的片段（空白、标点）都带 id 1；`ResolveForegroundLocked` 对 `colorId <= 1` 直接返回 0（= 用调用方前景），其他 id 与 `DefaultForeground` 相等时也返回 0（`ThemeContext.cs:29,70-78,99-101`）。
- **RaTeX 默认色用哨兵色保留 `\color`**：`RaTeXMathRenderer.Layout` 总是把 `RaTeXMathLayout.DefaultColorSentinel`（`(0.0123, 0.0456, 0.0789, 1)`，`RaTeXMathLayout.cs:16`）当成默认色传给原生（`RaTeXMathRenderer.cs:53`），绘制时用 `IsSentinel` 容差 1e-4 判断"该用 foreground"（`RaTeXMathLayout.cs:255-270`），显式 `\color` / `\textcolor` 返回真实颜色从而被保留（测试 `RaTeXMathRendererTests.cs:96` 断言红色与哨兵色同时存在）。别把这个哨兵换成真实前景色——那会让 `\color` 与默认色不可区分。
- **`\fbox` / `\boxed` 边框的历史包袱**：原生补丁 `native/patches/0001-enclose-border-uses-current-color.patch` 已让边框使用默认颜色，所以 `RaTeXMathRenderer.HasUncoloredFrame` **恒返回 false**（`RaTeXMathRenderer.cs:74-76`）；但 `RaTeXMathLayout` 仍保留 `blackFramesAreDefault` 参数、`IsFrameRule` 与 `RectOp.Brush == null` 的路径（`RaTeXMathLayout.cs:27-38,133,252-253`），公开构造函数一律传 `false`（第 22-25 行）。旧注释里"边框固定黑色"的说法已经过时。
- **CJK / emoji 不是 KaTeX 字体能的**：字体名以 `CJK-` / `Emoji-` 开头时直接跳过 KaTeX 字体走系统回退（`KaTeXFonts.cs:48-50`）；系统回退先试 `FontFamily.Default` 再 `FontManager.TryMatchCharacter`（第 71-82 行），结果（含 `null`）按码点缓存，字形索引 0 视为缺字（第 52-61 行），缺字就直接跳过不画以免出豆腐块（第 25 行）。所有这些都要求 Avalonia 平台已初始化 —— 而图元只在 `Draw` 里构建（`RaTeXMathLayout.cs:56,81`），也就是界面线程首次绘制时，所以**不能**在后台线程构造 `GlyphRun`。
- **Mermaid 的 SVG 必须先展开 CSS 函数再交给 Svg.Skia**：Mermaider 0.15.1 的输出确实依赖 `color-mix(`（测试里对此有断言，`MermaidRendererTests.cs:114`），而 Svg.Skia 不支持 `color-mix()`，会画成黑色填充并丢连线（`CssColorResolver.cs:8-10`）——所以 `Render` 的顺序是 `BuildSvg`（内部 `MermaidRenderer.RenderSvg`，`MermaidDiagramRenderer.cs:137`）→ `ResolveSvg`（第 73 行）→ `SKSvg.FromSvg`（第 79 行），并且 `ResolveSvg` 之后整份文档里不应再出现 `var(` / `color-mix(`（测试 `MermaidRendererTests.cs:111`、`CssColorResolverTests.cs:55-56`）。混合规则：百分比归一化、预乘 alpha 在 sRGB 中插值、两者之和 <100% 时按比例降 alpha、非 sRGB 空间按 sRGB 近似（`CssColorResolver.cs:261-264,306-319`）；循环变量靠 `MaxDepth = 32` 终止（第 18、77、217 行）。变量来源只解析根 `<svg style="…">` 与 `<style>` 里的 `svg { … }` 规则（第 40-52 行），内联声明优先（第 68-70 行）。
- **Svg.Skia 版本被钉死在 5.1.1，托管依赖却被抬到 5.2.3，`Svg.Animation` 例外**：`Directory.Packages.props:21` 的集中版本写的是 `Svg.Skia 5.2.3`，`StreamMark.Mermaid.csproj:14-21` 用 `VersionOverride` 把它压回 `5.1.1`，并把 `Svg.Model` / `Svg.Custom` / `ShimSkiaSharp` / `Svg.SceneGraph` 覆盖到 `5.2.3`，`Svg.Animation` 保持 `5.1.1`。原因写在 csproj 注释与 `docs/decisions.md:31`：5.2.x 的 Svg.Skia 依赖 SkiaSharp 4.148 / HarfBuzzSharp 14.2，与 Avalonia 12.1.4（SkiaSharp 3.119.4 / HarfBuzzSharp 8.3.1.3）不兼容；而 5.1.1 的 `Svg.Model` 里 `TypeDescriptor` 用法会产生 IL2026，5.2.3 已修。Svg.Animation 5.2.x 依赖 SkiaSharp 4，所以不能跟着升。**把 `VersionOverride` 删掉就会拿 5.2.3 的 Svg.Skia，表现是原生 Skia 库冲突 / 崩溃，而不是编译错误。**
- **宿主主题色常带透明度，绝不能直接丢掉 alpha**：AtomUI 暗色的 `ColorText` 是 85% 的白、`ColorFillQuaternary`（代码块底）是 4% 的白，以前 `Opaque()` 只取 RGB，得到 `Bg = Fg = #F0F0F0`，Mermaider 把节点填充画成「前景 10% 叠在背景上」→ 白节点白字（亮色下是黑节点黑字）。现在的分工是：`DiagramBlockView.ResolveEnvironment`（`DiagramBlockView.cs:124-134`）先把代码底色叠到块背后真实的底色上（`BackdropColor` 沿可视树向上叠加祖先的纯色背景，找不到时用 #1E1E1E / 白，第 140-168 行），再把前景 / 强调色叠到该底色上；`MermaidDiagramRenderer.CreateOptions` 对仍带透明度的输入也用 `DiagramRenderContext.Flatten` 兜底（第 153-154、171 行）。全屏查看器的内容底色同样取这个不透明底色（`_surface`，第 101、268 行）。回归测试：`MermaidThemeTests.SemiTransparentHostColors_AreFlattenedOntoTheBackdrop_NotStripped`（`MermaidThemeTests.cs:63`，断言对比度 > 7）、`DiagramBlockViewTests.SemiTransparentThemeColors_AreFlattenedOntoTheRealBackdrop`（`DiagramBlockViewTests.cs:96`，断言三层底色叠加的结果与 `Flatten` 一致且 alpha 为 255）。
- **图表只在挂上可视树之后才渲染**：底色取决于祖先背景，没挂上时算不准（还会白渲染一次），`DiagramBlockView.Refresh` 在未挂载时只更新可见性（`DiagramBlockView.cs:95-110`），`OnAttachedToVisualTree` 再补上（第 181-188 行）；缓存键里有渲染器身份（`RuntimeHelpers.GetHashCode`，第 117-118 行），同一进程里两个配置不同的渲染器（比如不同配色方案）不会互相命中缓存（测试 `DiagramBlockViewTests.ThemeColorChange_RendersAgain_NotServedFromTheCache`，`DiagramBlockViewTests.cs:129`）。
- **图表高度只按宽度适配，6000px 是安全上限（旧的 900px 上限已删除）**：`FitDiagram` 取 `min(1, width / natural.Width)` 再乘 `min(1, MaxDiagramHeight / natural.Height)`（`DiagramBlockView.cs:306-317`，`MaxDiagramHeight = 6000` 在第 31 行）——和浏览器里 `max-width: 100%` 的 SVG 一致，高流程图不再被压到看不清文字（旧实现在 e01b99a 是 `900 / natural.Height`）。回归测试 `DiagramBlockViewTests.DiagramHeight_FollowsWidthFit_NotAFixedCap`（`DiagramBlockViewTests.cs:154`：4000 高保持原样、20000 高被压到 6000）。
- **默认配色复刻 mermaid.js 官方主题，靠两种手段，别只改其中一种**：节点 / 连线 / 文字 / 默认色用 Mermaider 的 `Surface` / `Border` / `Line` / `Fg` / `Muted` / `Default` 钉住（`Accent` 取节点描边色，决策菱形才不会偏色），并关掉渐变与阴影（`Gradient = false`、`Elevation = 0`、`Tint = null`）——见 `MermaidThemer.Apply`（`MermaidThemer.cs:82-111`）；子图（面板色 + 描边，去掉 Mermaider 的标题条 `path` / `line`）、连线标签（矩形、无描边、`rx/ry=4`、不透明）、以及胶囊 / 圆柱 / 菱形这些**由 `color-mix()` 推导出来的**节点填充与描边是 Mermaider 自己的涂法，选项改不了，所以 `MermaidThemer.PaintSvg` 用 `XDocument` 按 `subgraph` / `edge-label` / `node` 语义类重涂（第 119-235 行；`PaintNode` 只替换 `fill` / `stroke` 以 `color-mix(` 开头的属性，作者用 `style` / `classDef` 指定的字面量颜色与状态图起止标记的 `var()` 都不受影响）。Mermaider 固定为 0.15.1（`Directory.Packages.props:20`），输出结构变了要回来看这里。`DataPalette` 只对结构类图表（流程图 / 状态图 / 类图 / 时序图 / block，`MermaidThemer.Detect` 判定）换成同一个中性灰（`NeutralPaletteSize = 12` 个重复值，第 28、102-108 行）：它们的色板只给容器自动着色，不换的话子图标题会各有各的色相；饼图、甘特图、思维导图等的色板是分类色，换了就全变灰（测试 `MermaidThemeTests.ChartDiagrams_KeepTheirCategoricalColors`，`MermaidThemeTests.cs:247`）。**色板里放蓝色（例如 #123456）会被当作 `Info` 角色色相排除、静默回退到默认的 slate**，探测色板用途时要用灰色。
- **复刻的是观感，不是像素**：颜色取自 mermaid 12.2 在流程图上实际输出的样式表（`MermaidPalette.cs:6-9` 注释），布局仍由 Mermaider 决定，与浏览器不会逐像素一致；已知差异（未修）是带回边的图主链可能上下翻转、标签里的 `&lt;` 按字面显示。要做到像素级一致得换 merman（需要自建 Rust 原生库），**已评估并否决**（`docs/decisions.md:14,30`）。
- **`MermaidTheme.MermaidJsNeutral` 只影响亮色**：`MermaidPalette.For` 先判 `isDark`，暗色一律给 `DarkPalette`（`MermaidPalette.cs:29-34`，测试 `MermaidThemeTests.MermaidJsThemes_UseTheOfficialPalette` 的暗色两行期望值相同，`MermaidThemeTests.cs:80-83`）。`MermaidTheme.Native` 走的是"没有调色板"这条路：`CreateOptions(context)` 与 `CreateOptions(context, Native)` 结果相等（测试 `NativeTheme_KeepsTheHostDerivedOptions`，第 100 行），子图仍由 Mermaider 按色板着色（测试 `NativeTheme_LeavesSubgraphsToMermaider`，第 175 行）。
- **静态图表缓存的容量淘汰不释放资源**：`DiagramCache.Add` 超容量时只 `Items.Remove` + `Order.RemoveFirst`（`Rendering/DiagramBlockView.cs:396-400`），没有调用 `DiagramResult.Dispose`，而 `SkiaPictureDiagram` 的 `SKPicture` / `SKSvg` 只由 `PictureHandle.Release` 释放（`SkiaPictureDiagram.cs:74-87`，没有终结器）—— 淘汰后的原生图元要等所有绘制操作也释放（`PictureDrawOperation.Dispose`，第 142 行）才可能归零，静态缓存本身不再持有引用。**这一条我只从代码读出，没有实测泄漏**：(unverified)。
- **`Draw` 可能晚于 `Dispose`**：自定义绘制操作在渲染线程执行，`PictureHandle` 因此做引用计数，`DiagramResult` 或场景里的绘制操作谁是最后一个持有者谁负责释放（`SkiaPictureDiagram.cs:15-18,45,50`）；`Dispose` 幂等（`Dispose` 里 `Interlocked.Exchange` 再 `Release`，测试 `MermaidRendererTests.cs:208`）。
- **三个插件的实例语义不一致**：`RaTeXPlugin` 默认共享 `RaTeXMathRenderer.Shared`（`RaTeXPlugin.cs:10`，因此缓存与 `Clear()` 是进程级的，测试 `PluginSystemTests.cs:171` 断言 `legacy.Registry.Math` 与插件注册的是同一实例），`TextMatePlugin` 与 `MermaidPlugin` 每次新建（`TextMatePlugin.cs:10`、`MermaidPlugin.cs:10`）—— 后者意味着多份 `MarkdownServices` 会各自加载一遍语法、各自渲染同一张图表（只有视图侧静态缓存能省掉一部分）。
