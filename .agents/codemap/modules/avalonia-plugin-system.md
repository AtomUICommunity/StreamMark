# Avalonia 插件体系与服务解析

`IMarkdownPlugin` 在 `Configure(MarkdownPluginBuilder)` 里一次性登记语法（白名单组件、Markdig 扩展、映射）、渲染（块组件视图 / 行内组件 / 围栏视图 / 公式 / 高亮 / 图表）与交互（代码块头部操作）；宿主把插件塞进 `MarkdownServices`，附加属性 `MarkdownServices.ServicesProperty` 把这份服务集合下发给整棵可视子树，首次访问时汇总成不可变的 `PluginRegistry`，注册表同时给出文档解析要用的 `Profile`。同一个 `MarkdownServices` 还携带一批**不进注册表**的界面选项（代码块选项、链接策略、引用来源、右键菜单与菜单文字、HTML 颜色策略、图片管线），它们在渲染时从 `context.Services` 现读。

**不负责：** 白名单标签的实际解析与 `ComponentSpec` 白名单表 / `MarkdigMapper` 的节点映射（`core-parsing-and-model`，`src/StreamMark.Core/Parsing/MarkdownProfile.cs:MarkdownProfileBuilder.AddComponent`、`src/StreamMark.Core/Parsing/HtmlComponentExtension.cs`）；块视图基类、`BlockViewFactory` 的分派分支与 `RenderContext` 的语义（`avalonia-text-rendering`，`src/StreamMark.Avalonia/Rendering/BlockViewFactory.cs:Create`）；`CodeBlockOptions` / `LinkPolicy` / `ISourceProvider` / `HtmlColorMode` 的**消费点**（`avalonia-text-rendering`，`src/StreamMark.Avalonia/Rendering/CodeBlockView.cs`、`TextSegmentView.cs`、`HtmlPaint.cs`）；右键菜单的实现与选区（`avalonia-selection`，`src/StreamMark.Avalonia/Selection/MarkdownContextMenu.cs:MarkdownContextMenu`）；RaTeX / TextMate / Mermaid 三个具体实现（`avalonia-extensions`，`src/StreamMark.RaTeX/RaTeXPlugin.cs`）；`Md.*` 主题资源与样式快照（`theme-and-styles`，`src/StreamMark.Avalonia/Rendering/MarkdownStyle.cs`）；图片取数 / 解码 / 缓存（`avalonia-images`，`src/StreamMark.Avalonia/Images/ImagePipeline.cs`，这里只持有 `MarkdownServices.Images` 引用）。

## State it owns
- `MarkdownServices._registry`（`src/StreamMark.Avalonia/Extensions/MarkdownServices.cs:17`）：`Registry => _registry ??= new PluginRegistry(this)`（:93）。注册表**只构建一次**，之后插件列表、`Math`、`Highlighter`、`Diagrams` 的任何后续改动都不生效（`MarkdownServices` 的属性都是 `init`，正确做法是换一个新实例）。首次访问的时机决定一切：`MarkdownView.CreateContext`（`src/StreamMark.Avalonia/MarkdownView.cs:173`）与 `MarkdownView.OnSourceChanged` 里的 `GetServices(this).Profile`（:107）都会顺手把注册表建出来。
- **界面选项不进注册表**：`CodeBlocks` / `Links` / `Sources` / `ContextMenu` / `MenuText` / `HtmlColors` / `Images` 都只在渲染时从 `context.Services` 现读（`CodeBlockView.cs:201`、`TextSegmentView.cs:713`、`MarkdownContextMenu.cs:36`），`PluginRegistry` 的构造（`PluginRegistry.cs:17-32`）完全不碰它们。所以换一份新的 `MarkdownServices` 后，这些选项靠 `ServicesProperty.Changed` → `InvalidateContext`（`MarkdownView.cs:44`、`:175`）在下一帧生效，而 `Plugins` 不会——`Profile` 已经固化在文档里（见「Invariants and traps」）。
- `PluginRegistry`（`src/StreamMark.Avalonia/Plugins/PluginRegistry.cs:13`）：`_blockComponents` / `_inlineComponents` / `_fenceViews` 是构造期从 builder 接过来的字典（builder 随后被丢弃，:28-30），`Diagrams` / `BlockActions` 是 `ImmutableArray`（:42、:44），`Profile` 是 `builder.Profile.Build()` 的产物（:32）。因此注册**只发生在构造阶段**，运行期没有任何增删入口；视图层拿到的是同一批工厂委托与同一个 `MarkdownProfile` 实例（`ReferenceEquals(fence, oldFence)` 就是靠这个身份判断复用，`src/StreamMark.Avalonia/Rendering/BlockViewFactory.cs:51`）。
- `MarkdownServices.Default`（`src/StreamMark.Avalonia/Extensions/MarkdownServices.cs:15`）是附加属性的默认值，即进程级单例：没设 `Services` 的所有视图共用它（以及它的首次访问即固化的注册表）；`ImagePipeline` 同理有 `s_defaultImages`（:31、:55）。
- `BlockStateStore` 的作用域是**每个文档视图一份**，不是每块一份：`MarkdownView._state`（`src/StreamMark.Avalonia/MarkdownView.cs:36`，输入属性变化时 `_state.Clear()`，:117）、`TranscriptPanel.EntryState.State`（`src/StreamMark.Avalonia/Transcript/TranscriptPanel.cs:41`）。`RenderContext` 收下它，缺省时自建一个空实例（`src/StreamMark.Avalonia/Rendering/RenderContext.cs:17`），并在 `With` / `WithHtml` 中透传（:52、:60）。
- 键是 `(顶层块 key, 状态名)`（`src/StreamMark.Avalonia/Plugins/BlockStateStore.cs:10`）：key 是块在原始源码中的起始偏移，源码只追加因此跨重解析稳定；状态名是字符串，已存在的有 `code.wrap`（`src/StreamMark.Avalonia/Rendering/CodeBlockView.cs:26`）、`code.expanded`（:27）、`code.state`（`src/StreamMark.Avalonia/Rendering/CodeBlockState.cs:59`）、`diagram.code`（`src/StreamMark.Avalonia/Rendering/DiagramBlockView.cs:58`）、`diff.mode`（`src/StreamMark.Avalonia/Rendering/DiffBlockView.cs:41`）、`diff.highlight`（:959）、`"collapsible.open:" + 组件名`（`src/StreamMark.Avalonia/Plugins/BuiltInComponentsPlugin.cs:65`）。约定只在界面线程访问（`BlockStateStore.cs:6`）。

## Contracts it exposes
- **`IMarkdownPlugin`**：`Name`（仅标识，注册表内不去重、不按名查找）+ `Configure(MarkdownPluginBuilder)`；`Configure` 在构造 `PluginRegistry` 时被同步调用一次，只允许**登记委托与工厂**，不要在里面做 IO 或反射（NativeAOT，`docs/architecture.md:57`）。
- **`MarkdownPluginBuilder` 各方法的语义**：`AddBlockComponent(name, factory, registerTag)` 把 `name` 映射为块视图工厂，默认同时把标签加进白名单（同名重复登记直接覆盖，`src/StreamMark.Avalonia/Plugins/IMarkdownPlugin.cs:68`）；工厂只负责 **new**，内容一律通过 `BlockView.Update` 下发，同名组件的新模型复用同一视图；`AddInlineComponent(name, renderer, kind, registerTag)` 默认按自闭合组件登记；`AddFenceView(language, factory, whileStreaming)` 按 `CodeBlock.Language` 精确匹配（字典是 `OrdinalIgnoreCase`，`IMarkdownPlugin.cs:40`）；`AddBlockAction(descriptor)` 是追加列表，无去重。
- **`IInlineComponentRenderer`** 的四个方法都带默认实现，插件按需覆写：`CreateRun`（自闭合组件 → `DrawableTextRun`，`null` 表示不显示，消费点 `src/StreamMark.Avalonia/Rendering/TextSegmentView.cs:1200`）、`GetStyle`（成对组件内部文字的 `InlineComponentStyle`，`null` 表示继承，消费点 :1282）、`ToPlainText`（复制到剪贴板时替代文本，`SelectionController.cs:432`）、`IsClickable`（决定悬停手型与 `TextSegmentView.ComponentClickedEvent`，`TextSegmentView.cs:652`、`:662`）。
- **`IMathRenderer` / `ISyntaxHighlighter` / `IDiagramRenderer`**：分别经 `UseMath` / `UseHighlighter` / `AddDiagramRenderer` 登记。`Layout` 必须线程安全（渲染层可能后台预排版）、失败返回 `null` 并给出 error（`src/StreamMark.Avalonia/Extensions/IMathRenderer.cs:7`）；`ISyntaxHighlighter` 来自 Core，按语言 `CreateSession` + `GetThemeColors`；`IDiagramRenderer.CanRender` 按语言认领、`RenderAsync` 可在后台线程跑、失败回退源码（`src/StreamMark.Avalonia/Extensions/IDiagramRenderer.cs:43`）。
- **`DiagramRenderContext` 的颜色约定**：`DiagramBlockView` 传进来的颜色**已经是**叠到真实底色上的不透明色（`src/StreamMark.Avalonia/Rendering/DiagramBlockView.cs:126-131`，环境由 `MarkdownStyle` 组出）；其它调用方（宿主自己的图表预览等）可以传半透明色，渲染器需要不透明色时用 `DiagramRenderContext.Flatten`（`src/StreamMark.Avalonia/Extensions/IDiagramRenderer.cs:8`、`:16`，Mermaid 侧的用法 `src/StreamMark.Mermaid/MermaidDiagramRenderer.cs:154`）。
- **`MarkdownServices.ServicesProperty`**：`inherits: true`，设置在窗口 / 会话视图 / 任意祖先上；`MarkdownView` 与 `TranscriptPanel` 都在静态构造里挂了 `Changed` 处理器，只做"作废当前 `RenderContext` 并请求下一帧"（`src/StreamMark.Avalonia/MarkdownView.cs:44`、`src/StreamMark.Avalonia/Transcript/TranscriptPanel.cs:225`）。
- **`CodeBlockOptions` 的默认值即行为**：`ShowLineNumbers` 默认 false、`CollapseAfterLines` 默认 40（`CollapseAfterLines = 0` 即从不折叠，`CodeBlockOptions.cs:11-12`）、`CollapsedLines` 默认 20、`ShowDownload` 默认 true、`DiffMode` 默认 `DiffViewMode.Markdown`（:31）。`Save` 为 null 时下载走窗口的 `IStorageProvider` 存 UTF-8（`src/StreamMark.Avalonia/Rendering/CodeBlockView.cs:158`）；`ExpandText` / `CollapseText` / `DiffModeText` 三个文字委托默认是英文（`CodeBlockOptions.cs:21-28`），每次显示时调用，宿主负责本地化。
- **`LinkPolicy` 的判定顺序**（`src/StreamMark.Avalonia/Extensions/LinkPolicy.cs:44`）：空地址 → `Block`；无协议或冒号出现在路径之后（相对地址 / `#锚点`）→ 看 `AllowRelative`；协议里夹带空白或控制字符（`java\tscript:`）→ `Block`；协议不在 `AllowedSchemes`（不区分大小写）→ `Block`；`RequireConfirmation` → `Confirm`；链接文字看起来是另一个主机（`LooksMismatched`，:79，剥掉 `www.` 后比较）→ `Confirm`；否则 `Allow`。宿主 `Override` 在内置规则**之后**调用（:41）。
- **`ISourceProvider`**：`GetSource(id)` 只在界面线程调用、必须快速返回（结果由宿主预先准备，`src/StreamMark.Avalonia/Extensions/ISourceProvider.cs:8`）；返回 `null` 时引用标签只显示标签文字（`TextSegmentView.cs:732`）。
- **`MarkdownContextMenu` 的菜单内容与时机**：`Attach` 时创建一个 `MenuFlyout`，`Opening` 时才 `Populate`（每次重建条目，`MarkdownContextMenu.cs:31`、`:43`）；条目固定为 复制 / 复制为 Markdown / 分隔线 / 全选 / 查找，文字全部来自 `services.MenuText(command)`（:47、:51），没有选区时前两项 `IsEnabled = false`（:48、:55-56）；"查找"只 `RaiseEvent(FindRequestedEvent)`（:59），宿主自己显示查找框（查找模型在 `MarkdownView.Search` / `TranscriptPanel.Search`，`MarkdownView.cs:206`、`TranscriptPanel.cs:1120`）。菜单用宿主主题的 `MenuFlyout` 外观（`MarkdownContextMenu.cs:18`）。
- **`Profile` 的用法约定**：宿主**必须**用 `services.Profile` 创建文档，四条路径都要传：`new StreamingDocument(services.Profile)`（`src/StreamMark.Core/Streaming/StreamingDocument.cs:37`，`null` 即回落到 `MarkdownProfile.Default`，:39）、`new MarkdownStream(profile: services.Profile)`（`src/StreamMark.Avalonia/MarkdownStream.cs:31`、`:35`）、`MarkdownEntry.FromText(text, profile)`（`src/StreamMark.Avalonia/Transcript/TranscriptEntry.cs:29`）、`MarkdownView.Markdown` 时由控件内部自建（`src/StreamMark.Avalonia/MarkdownView.cs:107`）。
- **兼容写法**：`Math` / `Highlighter` / `Diagrams` 三个属性等价于"注册一个只提供该能力的插件"，`PluginRegistry` 构造里 `Math = builder.Math ?? services.Math`（`src/StreamMark.Avalonia/Plugins/PluginRegistry.cs:25`）；`Diagrams` 则是 `[.. services.Diagrams, .. builder.Diagrams]`（:27），两者的优先级方向相反。

## How to extend
- **To add 一个插件**：① 实现 `IMarkdownPlugin`，在 `Configure` 里一次性登记（参照 `RaTeXPlugin`）；② 挂进 `new MarkdownServices { Plugins = [new MyPlugin(), ...] }` 并经 `MarkdownServices.SetServices(viewOrAncestor, services)` 下发（`src/StreamMark.Avalonia/Extensions/MarkdownServices.cs:105`）；③ 用 `services.Profile` 创建文档——`MarkdownEntry.FromText(text, services.Profile)` / `new StreamingDocument(services.Profile)` / `new MarkdownStream(profile: services.Profile)`（`samples/StreamMark.Gallery/Program.cs:84`、`:85`、`:89`、`:118`）。漏掉 ③ 的症状：插件注册的组件标签根本不会被解析（`Profile` 变了但文档用的是 `MarkdownProfile.Default`），标签按普通 HTML / 文本落到 `HtmlBlock` / 段落里，`TryGetBlockComponent` 永远不会被调用（`src/StreamMark.Avalonia/Plugins/PluginRegistry.cs:35` 的注释即为此）。
- **To add 行内 / 块级组件视图**：① 实现 `IInlineComponentRenderer`（只覆写需要的方法）或提供一个 `Func<ComponentBlock, BlockView>` 工厂；② `builder.AddInlineComponent(name, renderer, kind)` / `builder.AddBlockComponent(name, factory)`（`src/StreamMark.Avalonia/Plugins/IMarkdownPlugin.cs:66`、`:77`）；自定义视图类继承 `StackBlockView` 或 `BlockView` 并在 `OnUpdate` 里**按阅读顺序**消耗片段号（`src/StreamMark.Avalonia/Rendering/BlockView.cs:35`、`:45`）；③ 若视图要在回收后保留状态，把状态写进 `context.State`（键用 `(TopKey, 状态名)`，参照 `CollapsibleBlockView.OnUpdate` 的 `context.State.Get(topKey, StateName, defaultOpen)`，`src/StreamMark.Avalonia/Plugins/BuiltInComponentsPlugin.cs:84`）。漏掉 ③ 的症状：视图被虚拟化回收后展开 / 换行 / 图表视图选择全部回到默认值。
- **To add 代码围栏视图与块操作**：① `builder.AddFenceView("diff", code => new DiffView(), whileStreaming: false)`，视图需自己消费片段号（`segment++`）并实现 `MeasureOverride`（测试替身见 `tests/StreamMark.Avalonia.Tests/Plugins/PluginSystemTests.cs:78`）；② 头部按钮用 `builder.AddBlockAction(new BlockActionDescriptor(id, label, MarkdownIcons.X, block => block is CodeBlock { Language: "cs" }, ctx => Task.CompletedTask))`（`src/StreamMark.Avalonia/Plugins/IMarkdownPlugin.cs:127`）；③ 需要围栏信息串（路径 / 行号）时在 `Execute` 里用 `Plugins.CodeFenceInfo.Parse`（`src/StreamMark.Avalonia/Plugins/IMarkdownPlugin.cs:140`）。漏掉 ② 的症状：`AppliesTo` 恒为 false 时按钮不出现（`src/StreamMark.Avalonia/Rendering/CodeBlockView.cs:259`），而操作列表在**每次上下文变化时整体重建**（`UpdateActions`，:250；调用点 :192），漏掉 `AppliesTo` 的过滤条件会让操作出现在所有代码块 / 表格上。
- **To add 一个界面选项（如新的菜单文字 / 代码块开关）**：加 `MarkdownServices` 的 `init` 属性 + 一个有 `Default` 单例的选项记录（照 `CodeBlockOptions`，`src/StreamMark.Avalonia/Extensions/CodeBlockOptions.cs:4`），在消费点从 `context.Services` 现读（不要缓存进 `RenderContext` 之外的静态字段），并给文字类选项留一个 `Func<...>` 委托而不是常量字符串，宿主才能跟随界面语言。要在运行期换掉它，只需 `SetServices` 一个新实例（`MarkdownView.cs:44` 会作废上下文）。

## Invariants and traps
- **同名组件后登记者覆盖先登记者** — builder 用普通字典赋值（`BlockComponents[name] = factory`，`src/StreamMark.Avalonia/Plugins/IMarkdownPlugin.cs:68`），内置插件排在最前（`src/StreamMark.Avalonia/Plugins/PluginRegistry.cs:20`），所以宿主插件覆盖内置是**设计内行为**；`Profile.AddComponent` 同样是先 `RemoveAll` 同名再追加（`src/StreamMark.Core/Parsing/MarkdownProfile.cs:77-80`），两处必须同时覆盖，否则出现"解析成组件但视图还是内置的"或反之。
- **内置组件总是启用且无法关闭** — `IEnumerable<IMarkdownPlugin> plugins = [BuiltInComponentsPlugin.Instance, .. services.Plugins]` 是硬编码拼接（`src/StreamMark.Avalonia/Plugins/PluginRegistry.cs:20`），`details` / `think` / `citation` / `cite` 四个视图必然存在（`src/StreamMark.Avalonia/Plugins/BuiltInComponentsPlugin.cs:26-29`，均以 `registerTag: false` 登记，白名单标签来自 `ComponentSpec.BuiltIn`，`src/StreamMark.Core/Parsing/ComponentSpec.cs:20`）；**新增**：内置插件还硬编码了 `diff` / `patch` 两个围栏视图且 `whileStreaming: true`（:31-32），宿主同名 `AddFenceView` 同样能覆盖（排在后面）；未注册视图的 `ComponentBlock` 回落到 `ComponentContainerView` 而不是报错（`src/StreamMark.Avalonia/Rendering/BlockViewFactory.cs:13`）。
- **插件注册只用委托与工厂，不用反射** — `MarkdownPluginBuilder` 的字段全是 `Func<...>` / `IInlineComponentRenderer` / 记录类型（`src/StreamMark.Avalonia/Plugins/IMarkdownPlugin.cs:35-41`），Core 侧 `MapBlock<T>` 也只做 `is TNode` 判定后调委托（`src/StreamMark.Core/Parsing/MarkdownProfile.cs:85`）；库项目一律 `IsAotCompatible=true` 且裁剪警告视为错误（`docs/architecture.md:57`），所以插件里不要引入反射式注册 / 动态类型扫描。
- **注册表不可变，改动只在注册阶段** — 运行期没有任何 API 能往注册表里加东西；`Registry` 一旦被首次访问就固定（`src/StreamMark.Avalonia/Extensions/MarkdownServices.cs:93`），此后修改 `Plugins` 列表内容不会生效（属性本身也是 `init`）。想在运行期换插件只能换一个新的 `MarkdownServices` 实例并重新 `SetServices`。
- **`MarkdownServices` 变化不会重建自建文档** — 附加属性的 `Changed` 处理器只调 `InvalidateContext()`（作废 `RenderContext` 并请求下一帧，`src/StreamMark.Avalonia/MarkdownView.cs:44`、`:175`），而 `_ownDocument ??= new StreamingDocument(GetServices(this).Profile)`（:107）只在 `Markdown` / `Document` / `Stream` 变化且 `_ownDocument` 为 null 时重建。所以先设 `Markdown`、后 `SetServices` 的话，文档仍用旧 `Profile`，插件标签不被解析；正确顺序是先 `SetServices` 再设 `Markdown`（测试即如此，`tests/StreamMark.Avalonia.Tests/Plugins/PluginSystemTests.cs:131`）。**注意这与界面选项相反**：`Links` / `CodeBlocks` / `MenuText` 等不受此限制，它们不在 `Profile` 里，换实例后下一帧就生效。
- **相容属性与插件的优先级方向相反** — 公式与高亮是 `builder.Math ?? services.Math`（插件赢，`src/StreamMark.Avalonia/Plugins/PluginRegistry.cs:25`），图表是 `[.. services.Diagrams, .. builder.Diagrams]` 且 `FindDiagramRenderer` 返回**第一个** `CanRender` 匹配（:27、:48），因此旧写法 `services.Diagrams` 反而排在插件前面、先被命中。`Math` / `Highlighter` 是单值（后登记覆盖先登记），`Diagrams` 是列表（先登记者优先）。
- **围栏视图默认只在代码块闭合后替换，但内置 `diff` / `patch` 例外** — `FindFenceView` 要求 `!code.IsOpen || registration.WhileStreaming`（`src/StreamMark.Avalonia/Plugins/PluginRegistry.cs:63`），流式中途是普通 `CodeBlockView`；内置 `diff` / `patch` 声明了 `whileStreaming: true`（`src/StreamMark.Avalonia/Plugins/BuiltInComponentsPlugin.cs:31-32`），所以未闭合的 diff 围栏从一开始就是 `DiffBlockView`，而图表块仍只在闭合后创建。`CanReuse` 用 `ReferenceEquals(fence, oldFence)` 判定（`src/StreamMark.Avalonia/Rendering/BlockViewFactory.cs:51`），因此同语言注册被替换（新注册表）时旧视图会被换掉，而围栏视图与 `CodeBlockView` 之间来回切换也会导致视图重建。
- **`AddBlockComponent(registerTag: true)` 会与 Core 的内置标签表合并**，`ComponentTable` 用 `OrdinalIgnoreCase` 查找、`BlockNames` 取小写（`src/StreamMark.Core/Parsing/ComponentSpec.cs:50`、`:58`），而 `MarkdigMapper` 把块级组件名统一 `ToLowerInvariant()` 后放进模型（`src/StreamMark.Core/Parsing/MarkdigMapper.cs:188`）——注册 `"Callout"` 与注册 `"callout"` 等价，视图工厂字典同样是 `OrdinalIgnoreCase`（`src/StreamMark.Avalonia/Plugins/IMarkdownPlugin.cs:38`）。
- **`BlockStateStore` 只在界面线程访问、且随文档生命周期清空** — `MarkdownView.OnSourceChanged` 里 `_state.Clear()`（`src/StreamMark.Avalonia/MarkdownView.cs:117`），因此换文档 / 重设 `Markdown` 会把折叠、换行、图表与 diff 视图选择全部重置；`BlockStateStore.Set` 要求 `T : notnull`（`src/StreamMark.Avalonia/Plugins/BlockStateStore.cs:15`），存可空类型（如 `CodeBlockState?`）会静默不写入。
- **菜单文字与代码块文字委托是"每次显示时调用"的** — `MenuText` 在 `MenuFlyout.Opening` → `Populate` 里逐条取（`src/StreamMark.Avalonia/Selection/MarkdownContextMenu.cs:47`、`:51`），`ExpandText` / `CollapseText` / `DiffModeText` 在视图更新时取（`src/StreamMark.Avalonia/Rendering/CodeBlockView.cs` 的 `_expand.Label` 一行、`DiffBlockView.cs:105`）。所以委托里可以做本地化查表，但**不要**在里面做重活（菜单每次打开都调）或返回会变的宽度相关文本。
- **`ContextMenu = false` 只关菜单，不影响选区与复制** — 拦截发生在 `Control.ContextRequestedEvent` 的隧道阶段（`src/StreamMark.Avalonia/Selection/MarkdownContextMenu.cs:34-40`），`Ctrl+C` / `Ctrl+A` 走的是 `SelectionController`（`src/StreamMark.Avalonia/Selection/SelectionController.cs:174-183`、`:347`、`:372`），与菜单无关。
